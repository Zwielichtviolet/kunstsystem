Kunstsystem — «Рупор искусства»

1. О проекте

Kunstsystem — это интерактивный справочник изобразительных стилей, который оформлен в эстетике компьютерного терминала. Проект опубликован по адресу https://zwielichtviolet.github.io/kunstsystem/, исходный код лежит в репозитории https://github.com/N-Strar/kunstsystem. Лицензия — MIT.

Сайт был вдохновлён сайтом https://wallsbreathe.netlify.app/, который представляет из себя сайт с информацией и ссылками на соцсети 3D художника (в нынешнее время разработчика), чьи творения мне очень нравятся. Сам Kunstsystem — это одностраничное приложение: переходы между стилями происходят без перезагрузки страницы, состояние навигации хранится в хэше адреса, а пользовательские настройки — в localStorage. Выполнено все так чтобы ощущалось как небольшой терминал, в котором можно открыть стиль, ввести команду и посмотреть картину.

2. Языки и технологии

Проект построен на HTML5, CSS3 и JavaScript в версиях ES5/ES6 без сторонних библиотек. HTML5 отвечает за семантическую структуру страницы, мета-теги для SEO, карточки Open Graph и Twitter. CSS3 реализует весь визуальный стиль: анимации, сетки, адаптивность, спецэффекты и таймлайн. JavaScript отвечает за всю логику: роутинг, командную строку, лайтбокс и работу с localStorage. Данные каталога хранятся в data.js в виде JSON-подобной структуры: стили, годы, описания, художники и работы. Для хранения кода и версионирования используются Git и GitHub, для публикации — GitHub Pages с автодеплоем из ветки main.

Внешних зависимостей нет: ни фреймворков, ни CDN, ни шрифтовых сервисов. После первой загрузки сайт работает даже при отключённом интернете, так проект остаётся полностью автономным и поддерживает стилистику терминала.

3. Структура проекта

Проект состоит из файла index.html — каркаса страницы с SVG-favicon, Open Graph/Twitter-тегами и подключением скриптов; style.css — всех стилей и анимаций, включая таймлайн; data.js — данных каталога стилей (DATA) и карты годов (YEARS); script.js — логики приложения: роутинга, CLI, лайтбокса и localStorage; LICENSE — лицензии MIT; папки img/ — 36 изображений картин и фон BG.jpg.

4. Назначение файлов

4.1. index.html

index.html — это основа сайта. В разделе <head> прописаны кодировка UTF-8, настройка под экраны разных размеров (viewport), краткое описание для поисковиков и подключение style.css. Там же лежит иконка сайта SVG прямо в виде data-URI: зелёный текст в терминальном стиле на тёмном фоне, без отдельного файла.

4.2. style.css

style.css отвечает за всё оформление. Для body задан фон страницы: фото img/BG.jpg и затемняющий градиент для читаемости; терминал центрируется. 

Изображения .art-image получают лёгкий фильтр «старения»; при наведении цвет возвращается, а картинка приближается.

4.3. data.js

data.js содержит только данные, без логики. Массив DATA — каталог стилей из 18 объектов. Каждый объект включает slug — имя для адреса страницы (#impressionismus), de — немецкое название, ru — русское название, artists — список художников и works — массив работ.

Объект YEARS — карта годов эти данные используются таймлайном в меню и командой timeline.

4.4. script.js

script.js содержит логику приложения. Роутинг следит за хэшем адреса: #bauhaus строит страницу стиля, пустой хэш — главное меню со списком стилей и таймлайном. На странице стиля отображается год возникновения. Открытый стиль запоминается в localStorage под ключом ks_last_slug, поэтому в меню появляется ссылка «открыть снова».

Таймлайн сортирует стили по годам из YEARS и строит интерактивную хронологическую ленту в главном меню.

Командная строка обрабатывает ввод пользователя. Поддерживаются команды: ls — список всех стилей; open <№ или имя> — открыть стиль; timeline — стили по годам возникновения; random — открыть случайный стиль; cat beschreibung.txt — прокрутка к описанию; index — вернуться в главное меню; whoami — «кто я»; date — текущие дата и время; clear — очистить вывод; hilfe — справка по командам. Стрелки ↑ и ↓ листают историю команд. 

История команд сохраняется в localStorage под ключом ks_cmd_history, до 50 последних команд; стрелки ↑/↓ работают как в настоящем терминале.

Лайтбокс открывает картину на весь экран по клику; закрывается кликом или клавишей Esc.

4.5. img/

В папке img/ находятся 36 изображений. BD.jpg — фон страницы за окном терминала и превью для Open Graph. Также здесь 26 картин классических стилей (Моне, Дали, Уорхол, Баухаус и другие) и 10 картин новых стилей (Ренессанс, Барокко, Классицизм, Модерн, Абстракционизм). Если изображение отсутствует, обработчик onerror заменяет его терминальной заглушкой [ signal fehlt ], поэтому сайт не ломается без картинок.

5. Архитектура

Браузер загружает index.html, который подключает style.css, data.js и script.js. В data.js находятся DATA с 18 стилями и YEARS с годами. Функция route() читает адрес: при пустом хэше вызывается renderIndex() и строится меню с таймлайном и ссылкой «открыть снова», при хэше вроде #bauhaus вызывается renderStyle() и строится страница стиля с годом. События обрабатывают клики по ссылкам, ввод команд с историей и клик по картине для лайтбокса.

Состояние навигации хранится в адресе страницы, поэтому ссылку на конкретный стиль можно скопировать и отправить, а кнопка «назад» браузера работает как в обычном многостраничном сайте. Пользовательские настройки — последний стиль и история команд — хранятся в localStorage.

6. Этапы разработки

Версия 1 работала на Netlify и была многостраничным сайтом: 14 HTML-файлов и общий style.css. Были обнаружены и исправлены дефекты: неверные alt-тексты у 8 изображений и дублирование правил в CSS.

Версия 2 на GitHub Pages стала результатом переработки в одностраничное приложение. Проект разделили на index.html, style.css и script.js; появились интерактивная командная строка с сокращёнными командами, полноэкранный просмотр картин, фон страницы и полупрозрачное окно терминала с размытием. Каталог расширился с 13 до 18 стилей.

Версия 3 — текущая. Данные вынесены из script.js в отдельный data.js (DATA и YEARS). Появились таймлайн «стили по годам» в главном меню и команда timeline, команды random для случайного стиля, история команд в терменале с навигацией стрелками ↑/↓, запоминание последнего стиля и ссылка «открыть снова» в меню.Добавленна лицензия MIT.

## Kunstsystem v4

### Новое в v4
- Первый запуск с локальным никнеймом; `whoami` и `w` выводят выбранное имя.
- Команда `.` очищает содержимое терминала.
- Таймлайн изначально свёрнут и поддерживает фильтр по эпохам.
- Добавлена отдельная статья «Религиозное искусство».
- Таксономия различает художественные стили, виды искусства/медиа и декоративно-прикладные ремёсла.
- Анимация фоновых огней и деликатный glitch-эффект с учётом `prefers-reduced-motion`.
- Кнопка «Поделиться» для сайта и статей.
- Общая система комментариев на Supabase (требует настройки владельцем сайта).
- Логика localStorage и Web Share вынесена в отдельные JS-файлы.
- GitHub Actions запускает проверки JavaScript, HTML-ссылок и изображений.

### Настройка общего обсуждения (Supabase)
1. Создайте проект в Supabase.
2. Выполните SQL из `supabase/comments.sql` в SQL Editor.
3. В `comments-config.js` укажите Project URL и публичный anon key.
4. Никнейм и комментарии будут отображаться в общем обсуждении статей.

**Безопасность и ограничения:** используйте только anon/public key, никогда не публикуйте `service_role` key. RLS включён; публичным посетителям разрешено читать и добавлять комментарии, но не редактировать и не удалять их. Для публичного запуска рекомендуется добавить CAPTCHA/защиту от спама и модерацию через Edge Function. Ник хранится в `localStorage` и закреплён только в пределах этого браузера: это не полноценная проверка личности, анонимный посетитель технически может очистить хранилище или указать чужое имя.

### Локальная проверка
Требуется Node.js 22 или новее:
```bash
npm test
```

### Visual update 4.0.1
The selected v4 visual direction is **Radio Terminal**: a restrained phosphor-green interface, dark atmospheric background, subtle amber status details, and artwork presented as the main content. The prebuilt tower-light animation has intentionally been removed so the project owner can create and integrate a custom background effect. Artwork uses contain-style presentation to avoid cropping. Share actions live in the page footer, and `.` clears only command output. The taxonomy includes separate overview pages for art forms/media and decorative-applied arts/crafts.
