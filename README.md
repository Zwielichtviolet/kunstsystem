# Kunstsystem — «Рупор искусства»

**Kunstsystem** — интерактивный справочник художественных стилей и направлений, оформленный как атмосферный компьютерный терминал. Проект объединяет каталог искусства, командную строку, хронологию направлений и галерею произведений в едином интерфейсе **Radio Terminal**.

- **Текущая версия исходников:** `4.1.1`
- **Публичный сайт:** https://zwielichtviolet.github.io/kunstsystem/
- **Репозиторий:** https://github.com/Zwielichtviolet/kunstsystem
- **Лицензия:** MIT

## Возможности

### Каталог искусства

- Каталог из 18 художественных стилей с немецкими и русскими названиями.
- Страницы направлений с описаниями, художниками и произведениями.
- Отдельные тематические обзоры, в том числе религиозного искусства, видов искусства и медиа, декоративно-прикладного искусства и ремёсел.
- Разграничение художественных стилей, видов искусства/медиа и прикладных художественных практик.
- Прямые ссылки на страницы направлений через URL-хэш: например, `#bauhaus`.

### Навигация и история

- Одностраничная навигация без полной перезагрузки сайта.
- Таймлайн художественных направлений по годам возникновения.
- Фильтрация таймлайна по эпохам; по умолчанию таймлайн свёрнут.
- Запоминание последнего открытого направления и ссылка «открыть снова» в главном меню.
- История введённых команд с навигацией клавишами `↑` и `↓`.

### Галерея

- Просмотр произведений внутри страниц направлений.
- Полноэкранный лайтбокс по нажатию на изображение.
- Закрытие лайтбокса кликом или клавишей `Esc`.
- Изображения показываются без обрезки, чтобы сохранять композицию произведений.

### Никнейм и комментарии

- При первом посещении можно выбрать никнейм.
- Выбранное имя используется в интерфейсе и командах `whoami` / `w`.
- Предусмотрена общая система комментариев на базе Supabase. Для её включения владелец сайта должен настроить собственный проект Supabase и заполнить конфигурацию.

### Дополнительные функции

- Команда случайного выбора художественного стиля.
- Возможность поделиться сайтом или отдельной страницей.
- Адаптация интерфейса для мобильных экранов.
- Поддержка `prefers-reduced-motion` для пользователей, предпочитающих уменьшенную анимацию.
- Автоматические проверки проекта через GitHub Actions.

## Командная строка

Командная строка — один из основных способов навигации по Kunstsystem. Команды вводятся в поле терминала.

| Команда | Сокращение / аргументы | Действие |
|---|---|---|
| `hilfe` | `help`, `h`, `?` | Показать справку |
| `ls` | `l` | Вывести список направлений |
| `open` | `op` + номер или название | Открыть художественное направление |
| `timeline` | `tl` | Показать направления по годам |
| `random` | `zufall`, `rnd` | Открыть случайное направление |
| `cat beschreibung.txt` | — | Перейти к описанию страницы |
| `index` | `menu`, `m` | Вернуться в главное меню |
| `whoami` | `w` | Показать выбранный никнейм |
| `date` | — | Показать текущие дату и время |
| `clear` | `cls` | Очистить вывод командной строки |
| `.` | — | Очистить содержимое терминального вывода |

Примеры:

```text
ls
open 13
open bauhaus
timeline
random
whoami
```

Команды поддерживают историю ввода. Используйте `↑` и `↓`, чтобы перемещаться по предыдущим командам.

> Команда `.` очищает только вывод командной строки и не удаляет содержимое открытой страницы.

## Визуальная концепция

### Radio Terminal

Основное направление оформления Kunstsystem — **Radio Terminal**: сайт выглядит как интерфейс старого радиотерминала или специализированной информационной системы.

Ключевые элементы:

- тёмный атмосферный фон `img/BG.jpg`;
- полупрозрачное окно терминала;
- фосфорно-зелёная типографика и сдержанные дополнительные акценты;
- лёгкие эффекты свечения, сканирования и помех;
- произведения искусства как главный визуальный элемент страниц.

### Фоновые огни

На фоне расположены 50 световых точек. Сами точки прозрачные: видны только мягкие светящиеся ореолы. Для огней заданы индивидуальные интервалы мерцания, чтобы они не мигали синхронно.

Анимация учитывает системную настройку `prefers-reduced-motion`.

### Art Direction

Начиная с версии `4.1.0`, отдельные художественные направления получают собственные цветовые и визуальные акценты. Они меняют оформление страницы локально, не разрушая общий стиль терминала.

В версии `4.1.1` добавлены компактные графические сигнатуры направлений. Это CSS-композиции, а не внешние баннеры или изображения:

- геометрия;
- световые следы;
- сновидческие формы;
- экспрессивная волна;
- орнамент;
- архивная разметка.

Заставки остаются небольшими и не конкурируют с произведениями в галерее.

## Структура проекта

```text
kunstsystem/
├── .github/
│   └── workflows/
│       └── quality.yml          # Автоматические проверки GitHub Actions
├── img/                         # Фон и изображения произведений
│   └── BG.jpg                   # Фоновое изображение сайта
├── scripts/
│   └── check.js                 # Локальные проверки проекта
├── supabase/
│   └── comments.sql             # SQL-схема общей системы комментариев
├── index.html                   # HTML-каркас и подключения ресурсов
├── style.css                    # Оформление, адаптивность и анимации
├── data.js                      # Каталог DATA и хронология YEARS
├── script.js                    # Основная логика приложения и командной строки
├── storage.js                   # Работа с localStorage
├── share.js                     # Поделиться страницей / копирование ссылки
├── comments-config.js            # Настройки подключения Supabase
├── package.json                 # Метаданные и команда проверки
├── CHANGELOG.md                 # История изменений
├── README.md                    # Документация проекта
└── LICENSE                      # Лицензия MIT
```

### Назначение основных файлов

- **`index.html`** — семантический каркас страницы, метатеги, favicon, контейнер терминала, фоновые огни и подключения CSS/JavaScript.
- **`style.css`** — визуальная система Radio Terminal, страницы направлений, галерея, адаптивная вёрстка, эффекты и анимации.
- **`data.js`** — данные каталога `DATA` и хронологическая карта `YEARS`. Содержит информацию о направлениях, художниках и произведениях.
- **`script.js`** — маршрутизация по URL-хэшу, отрисовка страниц, командная строка, таймлайн, лайтбокс, никнейм и логика комментариев.
- **`storage.js`** — безопасная обёртка над `localStorage`.
- **`share.js`** — Web Share API с резервным копированием ссылки.
- **`comments-config.js`** — публичные параметры подключения Supabase. По умолчанию значения пустые.
- **`supabase/comments.sql`** — SQL для создания таблицы комментариев и политик Row Level Security.
- **`scripts/check.js`** — проверка синтаксиса JavaScript, повторяющихся HTML-id, локальных подключений и изображений, указанных в каталоге.
- **`CHANGELOG.md`** — подробная история изменений проекта.

## Технологии и архитектура

Проект построен на нативных веб-технологиях:

- HTML5;
- CSS3;
- JavaScript (ES5/ES6);
- localStorage;
- Web Share API и Clipboard API (при наличии поддержки браузером);
- Supabase — необязательный внешний сервис для общих комментариев;
- GitHub Pages — публикация сайта;
- GitHub Actions — автоматизированные проверки.

Сторонние JavaScript-фреймворки и сборщик не используются. Внешние CDN и шрифтовые сервисы для основного интерфейса не требуются.

### Как работает приложение

1. Браузер загружает `index.html` и подключённые ресурсы.
2. `data.js` предоставляет каталог направлений и данные таймлайна.
3. `script.js` читает URL-хэш и отображает главное меню, страницу направления или тематический обзор.
4. Командная строка выполняет команды и использует те же механизмы навигации.
5. `storage.js` сохраняет локальные пользовательские данные в браузере.
6. При настроенном Supabase блок комментариев обращается к общей базе данных.

URL-хэш позволяет открыть конкретное направление по прямой ссылке и использовать кнопки «назад» и «вперёд» браузера.

## Локальный запуск

Для просмотра сайта достаточно открыть `index.html` в браузере. Для более корректной локальной работы рекомендуется использовать локальный HTTP-сервер.

Например, при установленном Python:

```bash
python -m http.server 8000
```

Затем откройте:

```text
http://localhost:8000/
```

Для запуска проверок нужен **Node.js 22 или новее**. Установка сторонних npm-пакетов не требуется.

## Проверка проекта

Запустить проверки локально:

```bash
npm test
```

Команда выполняет `scripts/check.js`, который проверяет:

- синтаксис JavaScript-файлов;
- отсутствие повторяющихся `id` в `index.html`;
- наличие локальных CSS- и JS-файлов, подключённых в HTML;
- наличие изображений, на которые ссылается каталог в `data.js`.

GitHub Actions запускает проверки при изменениях в репозитории согласно настройкам workflow.

## Публикация на GitHub Pages

Сайт публикуется через **GitHub Pages** из ветки `main`.

Для обновления сайта:

1. Внесите изменения в файлы проекта.
2. Проверьте локальную работу сайта.
3. Запустите `npm test`.
4. Отправьте изменения в ветку `main`.
5. Дождитесь завершения GitHub Pages deployment.
6. Проверьте опубликованный сайт: главную страницу, страницы направлений, изображения и мобильную вёрстку.

В проекте используются относительные пути к локальным ресурсам (`style.css`, `data.js`, `img/...`). При добавлении новых ресурсов сохраняйте совместимость с размещением сайта в подпапке GitHub Pages `/kunstsystem/`.

## Общие комментарии Supabase

Система общих комментариев предусмотрена, но требует отдельной настройки владельцем сайта. Без настройки Supabase интерфейс проекта не получает доступ к общей базе комментариев.

### Настройка

1. Создайте проект в [Supabase](https://supabase.com/).
2. Откройте SQL Editor в панели проекта.
3. Выполните SQL из `supabase/comments.sql`.
4. Откройте `comments-config.js`.
5. Заполните параметры проекта:

```js
window.KS_SUPABASE_URL = 'https://YOUR_PROJECT.supabase.co';
window.KS_SUPABASE_ANON_KEY = 'YOUR_PUBLIC_ANON_KEY';
```

Используйте только публичный `anon` / publishable key, предназначенный для клиентского приложения.

**Никогда не помещайте в публичный репозиторий `service_role` key или другие секретные ключи.**

### Ограничения и безопасность

- В SQL включён Row Level Security (RLS).
- Публичным посетителям разрешено читать и добавлять комментарии.
- Публичным посетителям не предоставлены права на редактирование и удаление комментариев.
- Для публичного запуска рекомендуется добавить защиту от спама, CAPTCHA и модерацию, например через Supabase Edge Function.
- Клиентская проверка длины текста не заменяет серверную защиту.

## Хранение данных и ограничения

- Никнейм и история команд хранятся в `localStorage` текущего браузера.
- Никнейм не является учётной записью и не подтверждает личность посетителя.
- Данные `localStorage` не синхронизируются между устройствами и могут быть удалены пользователем вместе с данными браузера.
- Общие комментарии, если Supabase настроен, хранятся отдельно в базе проекта.
- Web Share API и Clipboard API зависят от поддержки браузером; предусмотрены резервные способы поделиться ссылкой.
- Без настроенного Supabase общая система комментариев не сможет работать как единое обсуждение для всех посетителей.

## История разработки

### Версия 1 — многостраничный сайт

Первая версия работала на Netlify и представляла собой многостраничный сайт: 14 HTML-файлов и общий `style.css`. В ходе проверки были обнаружены и исправлены дефекты: неверные `alt`-тексты у восьми изображений и дублирование CSS-правил.

### Версия 2 — переход к SPA

Проект был перенесён на GitHub Pages и переработан в одностраничное приложение. Основные файлы: `index.html`, `style.css` и `script.js`.

Появились интерактивная командная строка с сокращёнными командами, полноэкранный просмотр картин, фоновое изображение и полупрозрачное окно терминала с размытием. Каталог расширился с 13 до 18 художественных стилей.

### Версия 3 — структура данных и навигация

Данные были вынесены из `script.js` в отдельный `data.js`, содержащий `DATA` и `YEARS`.

Добавлены:

- таймлайн «Стили по годам» в главном меню;
- команда `timeline`;
- команда `random` для открытия случайного стиля;
- история команд с навигацией стрелками `↑` / `↓`;
- сохранение последнего открытого направления;
- ссылка «открыть снова» в главном меню;
- лицензия MIT.

### Версия 4 — визуальная и функциональная переработка

Четвёртая версия стала этапом частичной переработки проекта. Она развивалась постепенно и включала как функциональные улучшения, так и несколько визуальных итераций. Основной задачей стало развитие собственного образа Kunstsystem без отказа от терминальной концепции.

В серию изменений вошли:

- первоначальная настройка никнейма при первом посещении;
- команды `whoami` и `w`;
- свёрнутый по умолчанию таймлайн и фильтрация по эпохам;
- тематические обзоры и уточнение классификации художественных стилей, видов искусства/медиа и декоративно-прикладных практик;
- возможность поделиться сайтом и отдельными страницами;
- подготовка общей системы комментариев на Supabase;
- выделение хранения данных и функции «Поделиться» в отдельные JavaScript-файлы;
- автоматические проверки через GitHub Actions.

#### 4.0.1 — Radio Terminal

Выбрано основное визуальное направление проекта: тёмный интерфейс, фосфорно-зелёная типографика, сдержанные акценты и атмосфера радиотерминала. Переработаны терминальная рамка, галерея, карточки, текстовые блоки и мобильная компоновка. Кнопка «Поделиться» стала менее заметной и переместилась в нижнюю часть страниц. Команда `.` стала очищать только вывод командной строки.

#### 4.0.2 — Tower Lights

Интегрированы 50 фоновых огней с индивидуальным расположением и независимыми интервалами мерцания. Сохранён фон `img/BG.jpg`. Добавлена поддержка `prefers-reduced-motion`.

#### 4.0.3 — Halo Lights & Gallery Pass

Сами точки огней сделаны прозрачными: остаются только мягкие светящиеся ореолы. Сохранено индивидуальное мерцание. Дополнительно обновлена подача галереи: изображения получили больше пространства, спокойное оформление рамок и ненавязчивый акцент при наведении.

#### 4.1.0 — Art Direction Skins

Добавлены индивидуальные цветовые и визуальные акценты для художественных направлений. Оформление страниц, карточек и блоков описания меняется в зависимости от направления, сохраняя общую эстетику Radio Terminal.

#### 4.1.1 — Art Direction Signals

Добавлены компактные CSS-заставки перед описанием направлений. Используются шесть визуальных сигнатур: геометрия, световые следы, сновидческие формы, экспрессивная волна, орнамент и архивная разметка. Графика создаётся средствами CSS, без внешних изображений, и не конкурирует с произведениями в галерее.

> Серия V4 отражает этап разработки и визуального обновления проекта. Её итерации фиксируются в `CHANGELOG.md`.
